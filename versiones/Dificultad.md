En esta documentación anotamos algunos retos que tendrá el juego para que sea más divertido obligando al usuario a jugar.
1. Las gemas solo se combinan si es por intervención del usuario: vamos a mejorar la lógica para que ahora las gemas, ya no se combinen por si solas, ahora el usuario tendrá que unir unas con otras, para transformarlas en la siguiente gema, esta misma lógica aplica para todas las gemas, desde las esmeraldas hasta los diamantes, si estos chocan ya no se unen si no es por intervención humana del usuario. (Problema: Tenemos dos tipos de lógica según mi primera documentación de versión_1.md que le permite al usuario, 1. Presionar las esmeraldas y guiarlas, aquí no tenemos problema porque si el usuario al soltar la gema se une con la otra de la misma clase, todo bien, pero vamos con el segundo modo 2. El usuario puede lanzar la gema de forma brusca y aquí está el problema lanzar las gemas de forma brusca si no detecta el juego que fue por intervención humana entonces no se unirá, por lo que vamos a agregar un temporizador) si el usuario toca una gema y la arrastra hacia otra gema de la misma clase, al soltarla esta se unirá, y para el segundo metodo, al lanzar la gema deben pasar 2 segundos, si la gema no toca a otra gema de la misma clase 2 segundos después de soltarla, entonces ya no se unirá con nada. Otra cosa que debemos ajustar es que el juego no presente incoherencias en la lógica y diga "Toqué una gema y tuve una intervención del usuario hace 120 o 600 segundos, entonces me voy a unir", esto no puede suceder, porque la lógica tiene que ser directa, solo funcionando con los dos modos que ya establecimos. (Ojo: Esta lógica no se aplica a las perlas, estas deben caer al suelo y chocar con otra perla para convertirse en una esmeralda y lo pueden hacer sin intervención humana).
